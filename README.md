# FastChat UI

Современный веб-интерфейс для мессенджера **FastChat**, построенный на Vue 3 с использованием TypeScript. Приложение обеспечивает полный функционал для обмена сообщениями в реальном времени и управления чатами с авторизацией.

## 🚀 Возможности (Use Cases)

- **Авторизация и аутентификация**:
  - Регистрация нового пользователя
  - Вход в систему по логину и паролю (выдача Access и Refresh токенов)
  - Получение информации о текущем пользователе
  - Перенаправление неавторизованных пользователей на форму входа
  - Обновление токенов в фоновом режиме
  - Выход из системы
- **Управление чатами**:
  - Создание нового чата
  - Просмотр списка чатов текущего пользователя с последним сообщением
  - Просмотр сообщений и участников конкретного чата
  - Добавление новых участников в чат по username
  - Создание ссылки-приглашения в чат
  - Удаление чата (с проверкой прав владельца)
  - Исключение участников из чата (с проверкой прав владельца)
- **Отправка сообщений**:
  - Отправка текстовых сообщений в чат в режиме реального времени
  - Просмотр истории сообщений (с пагинацией - бесконечная прокрутка)
  - Удаление собственных сообщений
  - Редактирование собственных сообщений
  - Отметки об отправке, доставке и прочтении сообщений
- **Авторизация** — только участники чата могут читать/писать сообщения, только создатель может удалять чат
- **Уведомления**:
  - Получение непрочитанных уведомлений по SSE
  - Отметка о прочтении уведомлений

## 🛠️ Используемые технологии

| Технология     | Назначение                                                                     |
| -------------- | ------------------------------------------------------------------------------ |
| **TypeScript** | язык разработки                                                                |

## ✨ Запуск проекта

### Локальный запуск

```bash
# Установка зависимостей
npm install

# Запуск dev-сервера
npm run dev
```

### Запуск через Docker

Создание docker-сети:

```bash
docker network create fastchat-net
```

Сборка Docker-образа и запуск контейнера

```bash
docker-compose up -d --build
```

#### Конфигурация

Проект использует Docker Compose с одним сервисом `reverse-proxy`, который:

- Слушает порты 80 (HTTP) и 443 (HTTPS)
- Использует сертификаты из папки `certs/`
- Проксирует API запросы на backend-сервисы

После запуска приложение будет доступно по адресу:

- HTTP: `http://localhost` (перенаправляет на HTTPS)
- HTTPS: `https://localhost`

#### Остановка контейнеров

```bash
# Остановка и удаление контейнеров
docker-compose down

# Остановка с удалением volumes
docker-compose down -v
```

#### Просмотр логов

```bash
docker-compose logs -f
```

#### Переменные окружения

Создайте файл `.env` на основе `.env.template`:

```bash
cp .env.template .env
```

Основные переменные:

| Переменная      | Описание         | Значение по умолчанию |
| --------------- | ---------------- | --------------------- |
| `VITE_API_HOST` | Хост backend API | `localhost`           |

### Настройка SSL

Сертификаты находятся в папке `certs/`. Для использования своих сертификатов:

1. Замените `certs/cert.crt` и `certs/key.key`
2. Пересоберите Docker-образ: `docker-compose up --build`

## 🔌 API интеграция

### Auth API

| Эндпоинт                | Метод  | Описание                               |
| ----------------------- | ------ | -------------------------------------- |
| `/api/v1/auth/token`    | POST   | Вход в систему                         |
| `/api/v1/auth/register` | POST   | Регистрация                            |
| `/api/v1/auth/logout`   | DELETE | Выход                                  |
| `/api/v1/auth/refresh`  | POST   | Обновление токенов                     |
| `/api/v1/users/me`      | GET    | Получение данных текущего пользователя |

### Chats API

| Эндпоинт                            | Метод  | Описание                       |
| ----------------------------------- | ------ | ------------------------------ |
| `/api/v1/chats`                     | GET    | Список чатов пользователя      |
| `/api/v1/chats`                     | POST   | Создание нового чата           |
| `/api/v1/chats/:id`                 | GET    | Детальная информация о чате    |
| `/api/v1/chats/:id`                 | DELETE | Удаление чата (владелец)       |
| `/api/v1/chats/:id/members`         | DELETE | Покинуть чат                   |
| `/api/v1/chats/:id/members/:userId` | DELETE | Исключить участника (владелец) |
| `/api/v1/chats/:id/members`         | POST   | Пригласить участника           |
| `/api/v1/chats/:id/invite`          | GET    | Получить ссылку-приглашение    |
| `/api/v1/chats/invite`              | POST   | Присоединиться по приглашению  |

### Messages API

| Эндпоинт                              | Метод  | Описание                 |
| ------------------------------------- | ------ | ------------------------ |
| `/api/v1/messages`                    | POST   | Отправка сообщения       |
| `/api/v1/messages/:id`                | PATCH  | Редактирование сообщения |
| `/api/v1/messages/:id`                | DELETE | Удаление сообщения       |
| `/api/v1/chats/:id/messages/:id/read` | POST   | Отметить как прочитанное |

### Notifications API

| Эндпоинт                        | Метод | Описание                               |
| ------------------------------- | ----- | -------------------------------------- |
| `/service/notifications/`       | GET   | Список уведомлений                     |
| `/service/notifications/`       | PATCH | Отметить как прочитанные               |
| `/service/notifications/events` | GET   | SSE endpoint для real-time уведомлений |

### WebSocket Events

WebSocket подключение: `wss://{host}/api/v1/chats/{chatId}/ws`

События от сервера:

- `sent_message` — новое сообщение отправлено
- `message_deleted` — сообщение удалено
- `message_updated` — сообщение изменено
- `joined_user` — участник присоединился
- `left_user` — участник покинул
- `connect_user` — участник онлайн
- `disconnect_user` — участник оффлайн
- `read_message` — сообщение прочитано

## 🐛 Известные ограничения

- Dev-режим не поддерживает HTTPS (требуется reverse proxy)
- WebSocket требует настроенного proxy для работы через Nginx
- SSL сертификаты являются самоподписанными (браузер может показывать предупреждение)
